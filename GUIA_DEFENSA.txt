--------------------------------------------------------------------------
 1. Conectarse a la WiFi de la clase.
 2. Abrir 04. SERVIDOR\CONUNI_SOAP_DOTNET_SERVIDOR\CONUNI_SOAP_DOTNET_SERVIDOR.sln
    -> Compilar -> Compilar solucion -> cerrar ese Visual Studio.
    (Si junto al reloj esta el icono de IIS Express: clic derecho -> Salir)
 3. Clic derecho en Inicio -> Terminal (Administrador) -> Si.
 4. Ejecutar (cambiar RUTA por la ruta real de la carpeta del proyecto):

    powershell -ExecutionPolicy Bypass -File "RUTA\04. SERVIDOR\publicar_iis.ps1"

 5. Al final debe decir:  WSDL OK (HTTP 200)
    y mostrar la URL del adaptador Wi-Fi, por ejemplo:
       Wi-Fi   http://192.168.0.106:8085/WSConversion.svc
    ==> ESA IP SE LA PASA A LOS DEMAS.
    (Si no la muestra: comando  ipconfig  -> "Direccion IPv4" del Wi-Fi)
 6. Probar en el navegador: http://IP:8085/WSConversion.svc
    Debe salir "Servicio de WSConversion".

 Si la IP cambia (otra WiFi), volver a ejecutar el script.

--------------------------------------------------------------------------
 PREGUNTAS PROBABLES DEL INGENIERO
--------------------------------------------------------------------------
 * Que es SOAP?
   Protocolo de mensajes XML sobre HTTP. Cada llamada es un "sobre"
   (Envelope) con Header y Body. El contrato se publica en el WSDL.
   Usamos SOAP 1.1 con basicHttpBinding (WCF).

 * Diferencia .svc y .asmx?
   .svc es WCF (tecnologia moderna de Microsoft para servicios).
   .asmx es el servicio web clasico de ASP.NET. Publicamos los dos con
   las mismas operaciones; el .asmx trae formulario de prueba.

 * Arquitectura?
   Cliente-servidor orientada a servicios (SOA). 1 servidor WCF en IIS
   (puerto 8085) y 4 clientes: consola, escritorio, web y movil.
   El servidor tiene capas: Contratos (IWSConversion), Servicios
   (WSConversion) y Logica (Convertidores, Validacion, Autenticador).

 * Donde esta MVC?
   En los clientes, dentro de ec/edu/monster/:
     modelo/      -> solo datos con get/set (Conversion, ErrorServicio)
     vista/       -> pantallas (consola, formularios, .cshtml, .xaml)
     controlador/ -> recibe la accion de la vista y llama al servicio
     servicio/    -> cliente SOAP que habla con el servidor

 * Donde esta el Singleton?
   Una sola instancia, constructor privado, acceso por "Instancia",
   creado con Lazy<T> (seguro entre hilos).
     Servidor:   Autenticador.Instancia (lee Web.config una vez y guarda
                 los intentos fallidos de cada usuario)
     Consola y escritorio: ClienteConversion.Instancia (una sola ChannelFactory)
     Web:        AddSingleton<ClienteConversion>() en Program.cs
     Movil:      ClienteSoap.Instancia y ControladorConversion.Instancia
   Por que: no crear una conexion nueva en cada conversion y que el
   contador de intentos sea unico para todo el servidor.

 * Donde se valida?
   En el SERVIDOR: credenciales, 3 intentos y bloqueo de 2 minutos,
   cero absoluto (-273.15 C / -459.67 F / 0 K), longitud y masa no
   negativas. El cliente solo revisa que sea numero.
   Si algo es invalido el servidor responde un SOAP Fault
   (FaultException<ErrorServicio> con Codigo y Mensaje):
   VALOR_INVALIDO, REGLA_NEGOCIO o ERROR_SERVIDOR.

 * Donde estan usuario y clave? Por que no hay base de datos?
   En el Web.config del servidor (UsuarioServicio / ClaveServicio).
   Este proyecto es SIN BDD; las conversiones son formulas, no se guarda
   nada. El historial vive solo durante la sesion.

 * Cuantas operaciones tiene?
   17: login + 6 de temperatura + 6 de longitud + 4 de masa.
   Factores exactos: 1 ft = 0.3048 m, 1 in = 0.0254 m,
   1 mi = 1.609344 km, 1 lb = 0.45359237 kg, 1 oz = 28.349523125 g.

 * Por que IIS y no IIS Express?
   IIS Express solo acepta conexiones de la misma PC; para que los otros
   equipos se conecten por IP se publica en IIS (sitio CONUNI, puerto
   8085, regla de firewall "CONUNI SOAP 8085").

 * Por que .NET MAUI y no Xamarin?
   MAUI es el sucesor oficial de Xamarin.Forms (Xamarin perdio soporte
   en mayo de 2024). Mismo C# y XAML. El movil llama al SOAP armando el
   sobre XML con HttpClient.

 * Diagramas?
   Todos en SAP PowerDesigner (01. UML\03. DIAGRAMAS): casos de uso,
   actividad (carriles Usuario | Cliente | Servidor), secuencia DS_01 a
   DS_08, clases (servidor y clientes) y arquitectura (.eam).
   Documentos: ERS (IEEE 830), ECUD (CU01 a CU08), manual tecnico y PPT.

 SI ALGO FALLA
--------------------------------------------------------------------------
 "No se pudo conectar con el servidor"  -> IP mal escrita o servidor
     apagado. Probar el .svc en el navegador (Paso 2).
 Movil "el servidor tardo demasiado"     -> la app tiene otra URL; escribir
     la IP del servidor en el cuadro "Servidor SOAP".
 Web o movil "(Descargado)" en VS        -> falta C:\Program Files\dotnet\
     en la variable Path; agregarla y reiniciar Visual Studio.
 Error 500 "puertas de memoria"          -> cerrar programas (ya esta
     corregido en Web.config).
 Ctrl+F5 no hace nada                    -> Depurar -> Iniciar sin depurar
     o Ctrl+Fn+F5.
 Usuario bloqueado                       -> esperar 2 minutos.
 La red de la clase no deja conectar     -> hotspot de un celular y todos
     conectados ahi; volver a correr publicar_iis.ps1 para la nueva IP.
